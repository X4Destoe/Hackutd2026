## 1. Conventions

- **Time:** `sim_minute: int`, minutes since scenario start (storm onset = 0, negative = before).
  The display time is derived: `scenario.start_iso + sim_minute`. `None` = never/unknown.
- **Money:** `int` USD cents. **Distance:** `float` miles. **Coordinates:** `lat`, `lon` floats (WGS84).
- **IDs:** prefix + zero-padded number, generated by `app.shared.ids.new_id(prefix)` at runtime or fixed in seed:
  `CUS-0001` customer · `CASE-0001` · `MSG-000001` · `NODE-*` nodes use typed prefixes below ·
  `RES-001` resource · `RSV-0001` reservation · `ADJ-01` adjuster · `OFR-0001` offer ·
  `BLD-01` building · `ACT-001` action plan · `WO-001` work order.
  Node IDs: `GEN-1` generation, `SUB-1` substation, `FDR-1A` feeder, `PMP-1` pump station,
  `WZ-1` water zone, `HOME-0001` home (one per customer), `BLD-01` building node (same as building id),
  `SYS-BLD-01-GEN` building system (`-GEN` generator, `-HVAC`, `-COOL`, `-PIPE`).
- **JSON field names:** `snake_case` everywhere (backend and frontend generated types).
- **Lists in responses:** plain arrays. No pagination envelope; use `?limit=` (default 200).

## 3. Models (`app/shared/schemas.py`, Pydantic v2)

`?` = optional (default `None`). `[]` = list (default empty).

### Graph (owned by `cascade`, stored in `core` store)
```
Node:        id, kind: NodeKind, name, lat?, lon?, state: NodeState = ok,
             buffer_hours: float = 0           # survival time after losing supply (fuel, thermal)
             buffer_left_hours?: float         # live countdown once on backup
             lost_supply_at?: int, failed_at?: int,
             predicted_fail_at?: int, predicted_cause?: str,   # set by prediction pass
             attrs: dict = {}                  # kind-specific (e.g. home insulation, pump capacity)
Edge:        id, src: str, dst: str, kind: DependencyKind, group: str = "main"
             # dst DEPENDS ON src. Edges into dst with the same group are redundant (OR);
             # different groups are all required (AND).
ChainStep:   node_id, at_minute: int, predicted: bool, reason: str
CascadeChain: id, root_id, steps: [ChainStep], customers_affected: int, buildings_affected: int

GraphSlim:   nodes: [Node], edges: [Edge]      # GET /api/graph (homes omitted unless ?homes=1)
```

## 5. Events (bus + SSE)

In process: `app.shared.events.bus.emit(type, payload)` and `bus.on(type, handler)`. Handlers are sync and
must be fast (heavy work gets scheduled as an asyncio task). **Every event is also streamed** on `GET /api/events` as
`event: <type>\ndata: <json payload>\n\n`. The frontend uses events only to refresh queries, so payloads stay small.

| Type | Payload | Emitted by | Typical consumers |
|---|---|---|---|
| `clock.tick` | `{sim_minute}` | core | everyone (via tick order), UI clock |
| `demo.state` | `DemoStatus` | scenario | UI |
| `scenario.event` | `{at, code, description}` | scenario | cascade, UI log |
| `weather.updated` | `{temp_f, wind_chill_f}` | scenario | cascade |
| `node.changed` | `{node_id, kind, state}` | cascade | outreach, resources, portfolio, UI |
| `prediction.updated` | `{count, soonest: [Prediction] (≤10)}` | cascade | resources, portfolio, UI |
| `customer.affected` | `{customer_id, node_id, cause, predicted: bool}` | cascade | outreach |
| `case.created` / `case.updated` | `{case_id, tier, status, score}` | triage | resources, dispatch, impact, UI |
| `intake.parsed` | `{case_id, extraction: IntakeExtraction}` | outreach | triage |
| `message.sent` / `message.received` | `{message_id, party_type, party_id, case_id, kind}` | messaging | outreach, dispatch, UI |
| `resource.changed` | `{resource_id, status, capacity_used}` | resources | UI |
| `reservation.changed` | `{reservation_id, case_id, resource_id, status}` | resources | triage, UI |
| `offer.changed` | `{offer_id, case_id, adjuster_id, status}` | dispatch | triage, UI |
| `action.proposed` / `action.changed` | `{action_id, building_id, kind, status}` | portfolio | UI |
| `workorder.changed` | `{workorder_id, status}` | portfolio | UI |
| `kpis.updated` | `Kpis` | impact | UI |
